# チュートリアル1. ヘアサロンの予約相談チャットボット

お客様とチャットで相談します。受付担当のワーカー「あかり」は、お客様のご用件（サロンのご案内、ご予約、予約の確認、予約の変更やキャンセル、そのほかのご用件）を見つけ、ご用件ごとに必要なことを伺い、聞いたことを表に一行ずつ記録します。何がまだ残っているか、今どのステップかは、ワーカーではなくプログラム（**会話ナビゲーター**）が記録を見て決めます。予約が入るとスタイリストに相談の要約メールが届き（会話すべてが添付され、承認とお断りのリンクが入っています）、スタイリストが承認したときに、お客様に確定のショートメッセージが届きます。

## 完成するとこうなります

「ヘアサロン こもれび」（架空のサロン）にはスタイリストが三人（高橋、中村、小林）いて、数日分の予約がすでに入っています。火曜日は定休日です。メニュー（カット、パーマ、カラー、トリートメント）はスタイルごとに料金と所要時間が違い、料金は税込の円です。

相談はこのように進みます。

```
あいさつ → ご用件を見つける → ご用件ごとに一つずつ:
                    - サロンのご案内: サロン案内の文書から探して答える
                    - ご予約: お名前、携帯電話番号、メニュー、スタイル、希望の日時、スタイリスト（任意）、
                              メニューごとの質問（salon.json）、空いている時間一つにお客様の了承 → 予約
                    - 予約の確認: お名前と携帯電話番号でご本人確認 → 予約をお伝えする
                    - 予約の変更やキャンセル: ご本人確認 → どの予約か、変更かキャンセルか、新しい時間（キャンセルの理由は任意）
                    - そのほかのご用件: どんなご用件か（携帯電話番号は任意）→ サロンからお電話
      → 「ほかにお手伝いできることはありますか」（もう一度ご用件を見つける）→ 締めくくり
相談が終わると、フローが相談の記録を消します。
```

- あかりの仕事は、お客様と話し、聞いたことを保存ツール（`put`）で相談メモの表（`consult`）に書くことです。同じ項目をもう一度書くとその行が新しい値に変わり、前の値は履歴に残ります（お客様がカラーからパーマに気を変えると、`service` の行が一つ変わります）。
- 質問のたびに**会話ナビゲーター**（`workers/reception/navigator.py`）が記録をチェックリスト（`checklists.json`、`salon.json`）と照らし、ステップ（相談 `consult`、予約 `booking`、予約の確認と変更 `manage`）と**ステップ案内**を決めます。ステップ案内は「ご予約: お客様と話しながら、ご予約に必要なことを伺います。残り: ...」のように、残りの項目と記録済みの項目を言います。あかりが `put` をすると、ナビゲーターがもう一度呼ばれ、同じ質問の中で案内がすぐ変わります。
- 予約ツール（`book`）は予約ステップにだけあります。予約ステップは、了承を除く予約の項目がすべて記録されたときだけ開きます。希望の時間がすでに埋まっている、またはスタイリストが出勤しない日なら、案内がそう言い、空き時間ツール（`find_times`）で近い空き時間を探して、もう一度了承をいただくようにします。了承は、最後に決めた時間についてだけ数えます。
- 予約の確認、変更、キャンセルは**ご本人確認**が先です。お客様が伝えたお名前と携帯電話番号をプログラムが予約の記録と照らし（ブラウザの識別子ではなく）、合ったときだけそのお客様の予約を見せ、変更します。番号が違えば、ほかのお客様の予約があるかどうかも言いません。
- メニューの名前（スタイル）は `salon.json` にあるものだけが記録できます（表の `style` 欄が `salon.json` から値を読みます）。お客様がスタイルを決められないときは、「おまかせ」と記録し、あかりが雰囲気を伺っておすすめを二つか三つ出します。

## 作るのにかかる時間と準備するもの

約1時間。すでにできているプロジェクトを読み、設定を埋めて動かすチュートリアルです。

- Python 3.11〜3.13 と nextop 0.4.0（PyPI）: 下の0のステップの `setup.bat` がすべて入れます（自分で入れるなら `pip install -r requirements.txt`）。`requirements.txt` が nextop 0.4.0 に固定し、`project.json` の `"nextop": ">=0.4,<0.5"` がこのプロジェクトに必要なバージョンを伝えます（ほかのバージョンなら `nextop check` が直し方を教えます）。PyPI に出る前のビルドを試すときは、受け取った wheel ファイルで入れます: `setup.bat <wheel ファイルのパス>`。
- OpenAI API キー（既定です。ほかの OpenAI 互換 API でも動きます。下の設定を見てください）
- メールを送るアカウントの SMTP 情報（任意。なければメールの段階だけ飛ばされます）
- ショートメッセージのサービスはなくてもかまいません。既定はファイルに書き出す `outbox` 方式です。

モデルがなくても、3のステップまでは今すぐできます。プログラム側の部分（ナビゲーター、時間の計算、重なりの拒否、ご本人確認、ショートメッセージ、メール）は、モデルなしのテストコードで確かめます。

## このチュートリアルで学ぶ nextop の機能

- ワーカーの方式（`"mode"`）: お客様とチャットする自由質問のワーカー（あかり、`"ask"`）と、決まった仕事をする固定業務のワーカー（さき、`"task"`）を分ける
- 会話ナビゲーター（`navigator.py`）とステップ案内: 質問のたびに記録を見てステップと案内を決めるユーザーのコード。ステップごとに使えるツールとファイルサーバーが違います（予約ツールは予約ステップにだけ）
- ミッション（`mission.md`、どのステップでも同じ原則）、ステップの文章（`steps/<id>.md`）、ペルソナ（`persona.md`、誰かと話し方）
- チェックリストをコードではなく仕様ファイル（`checklists.json`、`salon.json`）に置く。表の選択欄（`choice`）が同じファイルから項目番号やメニュー名を読むプロジェクトの部品（`parts/field_type/choice.py`）
- 電話番号の欄の型（`phone`、`"country": "JP"`）: 090-1234-5678 のような書き方を一つの鍵（E.164、`+819012345678`）にそろえる
- 表のファイルサーバーと鍵: 同じ項目は上書きして履歴を残す（`consult`）、見せる深さ（`"show": 2`）でワーカーの入力に表の行をそのまま見せる
- 権限と範囲: チャットのお客様の識別子（`_subject`）で自分の記録だけを読ませる。予約の記録（`bookings`）はあかりのモデルには見えず（共通ツールなし、どのステップにも出さない）、ツールとナビゲーターがワーカーの権限で読み書きして、本人確認のできた分だけを伝える
- ツールが自分で記録を書く（予約ツールと予約変更ツール）と、フローの関数が書く（相談の記録を消す、スタイリストの答え、例の予約）の違い
- 返信チェック（`reply_check.py`）: ワーカーが返信を送る前にプログラムが文字を見て、日本語以外の文字が混ざっていたら理由を添えて書き直させる
- 有効期限（`expire_after`）: 終わらなかった相談の記録は一日後にコアが消す
- 文章の型と bm25 検索: サロン案内の文書（`shop_info`）を探して答える（ツール `query`、`get`）
- モデルなしのテスト: 偽の LLM で会話とフロー全体を確かめる

## ステップごとに進める

PowerShell で、このフォルダ（`ja/tutorial_01_hair_salon`）に移動して始めます。

### 0. インストール: setup.bat を実行

このフォルダの `setup.bat` をダブルクリックするか、PowerShell で `.\setup.bat` を実行します。最初の一回、必要なものをすべて自動で入れます。

- Python 3.11〜3.13 を探します。なければ winget で Python 3.12 を入れます（入れたあとはターミナルを開き直して `setup.bat` をもう一度実行）
- このフォルダに仮想環境 `.venv` を作り、`requirements.txt`（nextop、pytest）を入れます。`setup.bat C:\ダウンロード\nextop-0.4.0...whl` のように wheel ファイルのパスを渡す（または環境変数 `NEXTOP_WHEEL`）と、nextop だけをそのファイルで入れます。wheel は Python のバージョンに合っている必要があります（`cp311` なら Python 3.11）
- `.env` がなければ `.env.example` をコピーして作り、埋める必要のある名前だけを表示します
- モデルなしのテストを走らせ、すべて通れば最後に `Setup OK` と入った nextop のバージョンが出ます

何度実行してもかまいません（すでにある `.venv` と `.env` はそのままにします）。以下のコマンドは、仮想環境を有効にしてから実行します。

### 3. 例の予約を入れて、モデルなしでテストする

```powershell
python seed.py --reset
python -m pytest -q tests
```

`9 example bookings written` と表示され、テストは `45 passed` と出れば成功です。`schedule.html`（プロジェクトのフォルダに作られます）をブラウザで開くと、日ごとの表に確定した予約が青い欄で見えます（承認待ちの予約は点線の欄）。テストが確かめること:

- ご用件がなければ相談ステップで、案内は「ご用件を伺う」
- ご予約のご用件なら、残りの項目を項目番号（`name`、`phone`、`service`、`style`、`wish_time`、メニューごとの `color_want` ...）で言い、記録されたメニューの質問だけを数える
- 了承を除く予約の項目がすべて記録されたら予約ステップ。希望の時間が空いていれば「提案して了承をいただく」、了承が記録されれば「予約ツールで予約する」
- 希望の時間が埋まっていれば案内が別の時間を探すよう言い、了承があっても予約ツールが断る。了承のあとに時間を変えたら、了承をもう一度いただく必要がある
- 同じ項目をもう一度書くと最後の値が残り（履歴に前の値）、メニューを変えるとそのメニューの質問に変わる
- メニューにないスタイルはコアが受け取らない。メニューごとにスタイルは一つ。スタイルを決められない（おまかせ）ときは、雰囲気を伺ってメニューから選ぶよう案内する
- 料金と所要時間は、お客様が選んだスタイルから計算される。スタイルの所要時間に足りない時間は空きと数えない
- 一つのメッセージにご用件が二つ（予約と駐車場の質問）あれば、どちらも案内に出る
- 形の違う答え（電話番号、日時、「山田花子です」のような名前）は、もう一度書かせる。仕様にない項目番号はコアが受け取らない
- ほかのお客様のチャットには記録が見えない
- 予約ツールは相談ステップには渡されない。チャットで予約すると、予約の記録、`schedule.html`、お客様の表が書かれ、予約のご用件は終わりと記録され、その予約のチェックリストの行は消える
- ご本人確認: 番号が違えば何も教えない。別のブラウザでも、お名前と番号が合えば予約が見つかる。ご本人確認の前は、予約があるかどうかも言わない
- 変更とキャンセル: ご本人確認の前は断る、ほかのお客様の予約は断る。キャンセルすればその時間は空きに戻り、時間を変えれば承認待ちに戻る
- さきの相談の要約とみおのメモがスタイリストのメールに載り、承認の答えは一度だけ効く
- 予約やキャンセルを処理したその質問では、案内が「たった今処理した」と今の予約の状態を言う
- 相談が終わると、そのお客様の相談の記録だけが消える
- 返信チェック: ひらがな、カタカナ、漢字、数字、記号、料金、時刻は通り、ラテン文字やハングルなどが混ざった返信は、混ざった語を示して書き直させ、二度目も混ざっていれば代わりの返信（`reply_fallback`）を送る。メニューの名前はそのまま通る

### 4. サロン案内の文書の索引を作る

```powershell
nextop index --file-server shop_info
```

エラーなく終われば成功です（`shop_info` の二つの文書 `menu.md` と `shop.md` が登録されます）。文書を直したら、もう一度実行してください。

### 5. フローの検査

```powershell

```

`OK: ヘアサロン予約 (workers 3, tools 5, flows 4, file servers 4)` と出れば成功です。

### 6. チャットを開く

```powershell
python chat_server.py
```

ブラウザで http://127.0.0.1:8771 を開いて相談してみてください。`http://127.0.0.1:8771/schedule` では、予約の状況の表が見られます。「相談を終える」ボタンを押すと、その相談の記録が消えます。終わるときは Ctrl+C。

試してみる会話:
- 「カラーを予約したいです」: あかりが残りのことを一度に一つずつ伺い、そろったら空いている時間を一つ、スタイリストの名前と一緒に提案します
- すでに予約された時間（`schedule.html` の青い欄）をわざと選ぶ: あかりがその時間は取れないと言い、近い空き時間を提案します
- 途中で「カラーではなくパーマにします」: パーマの質問に変わります
- 「カットを予約したいのですが、駐車場はありますか」: 二つのご用件をどちらも片付けます
- 別のブラウザ（またはシークレットウィンドウ）で「予約を確認したいです」: お名前と番号を伺い、合えば予約をお伝えします。番号を間違えると何も教えません
- 携帯電話番号を伝えたくないと言う: なぜ必要か、ないとこのチャットで時間選びに進めないことを伝え、お電話での予約をおすすめします

### 7. 結果を確認する

予約が入ると、`booking_notes` フローが裏で動きます。数秒後に次のように確かめます。

- `memos/<予約番号>.memo.md`: スタイリストのメールと同じ内容、`memos/<予約番号>.chat.txt`: メールに添付される会話すべて。予約を変更したときは `memos/<予約番号>.change.md`
- スタイリストのメールボックス（テストモードでは `OFFICE_EMAIL`）: 承認とお断りのリンク。メールを設定していなければ、メモのファイルだけが残り、メールは送られません
- `runs/<実行番号>/`: 実行の記録。チャットの一つのメッセージが一つの実行で、ブロックのフォルダの `navigator.jsonl` に、ナビゲーターが選んだステップと案内が残ります

スタイリストになって答えます。メールの承認リンクをブラウザで開けばできます（チャットサーバーが動いている必要があります）。サーバーを通さずに済ませるにはコマンドを使います。

```powershell
python approve.py 2026-11-30-1300-takahashi              # 承認: 確定、お客様に確定のメッセージ
python approve.py 2026-11-30-1300-takahashi --decline    # お断り: その時間が空きに戻る、お客様にご案内のメッセージ
```

そのあと `outbox/sms_<時刻>.txt` にお客様へのメッセージが残り、`schedule.html` の点線の欄が青い欄に変わります（お断りすれば消えます）。予約番号は `<日付>-<時刻>-<スタイリストの識別子>` です。

## どう動くか

```
[お客様のチャット画面] --メッセージ--> chat_server.py --> あかり (reception, ask)
 (会話 + お客様の識別子)                                     |
                             navigator.py: consult と bookings を読み、ステップとステップ案内を決める
                                                |
          consult ステップ  ツール: price_quote, put, get, query
          booking ステップ  ツール: find_times, book, price_quote, put, get, query
          manage ステップ   ツール: verify_customer, find_times, change_booking, put, get, query

book            --> bookings に予約（承認待ち）、customers に髪のメモ、schedule.html、consult のご用件を終わりに
                --> chat_server が裏でフロー booking_notes: load_visit --> さき (要約) --> みお (メモ) --> mail_designer
verify_customer --> 名前と電話番号を予約の記録と照らす（結果だけを返す）
change_booking  --> ご本人確認をやり直し --> bookings を書く、schedule.html、スタイリストにメール、consult のご用件を終わりに
相談を終える    --> フロー chat_end (close_chat: このお客様の consult の行を消す)
スタイリストのリンク --> フロー decide (decide_booking: 確定またはお断り、お客様にメッセージ)
```

- **記録と判断を分けます。** お客様の言葉の意味を聞き取って記録するのはあかり（LLM）の仕事で、その記録から何が残っているか、時間が空いているか、本人か、今どのステップかはプログラムが決めます。だから、あかりに「料金ツールは一度だけ」のような付け足しの規則はありません。
- **ご用件の行**: あかりはご用件ごとに `purpose_<id>` の行（`words`: お客様の言葉、`state`: `open`）を残します。一つのメッセージにご用件が二つあれば二行です。予約と変更のご用件は、ツールが終わり（`done`）と書き、サロンのご案内、予約の確認、そのほかのご用件は、あかりが答えたあとで書きます。対応中の予約、予約の確認、変更のご用件のうち先に書かれたものがステップを決め、サロンのご案内とそのほかのご用件は、どのステップでも案内に一緒に出ます。
- **上書きと履歴**: `consult` の鍵が `item` なので、同じ項目をもう一度書くとその行が変わり、前の値は行の `history` に残ります。お客様ごとに別々（鍵にお客様の識別子が入る）なので、ほかのお客様の同じ項目と混ざりません。
- **見せる深さ**: `consult` と `customers` の権限の行に `"show": 2` があり、あかりの入力に、その表の行が欄の値と一緒にそのまま出ます。あかりは `list` を呼ばなくても、記録を見られます。
- **了承**: 予約ステップの `agree` は、希望の時間（`wish_time`）とスタイリスト（`designer`）が最後に変わったあとに書かれたときだけ数えます（行の `updated` の時刻で比べます）。その時間が空いていなければ、了承があっても数えず、案内が別の時間を探させます。予約ツールも同じ規則で確かめ直します。
- **予約の記録はあかりのモデルには見えません。** `bookings` の `type.json` は `"tools": []` で共通ツールがなく、どのステップの `file_servers` にも `bookings` はありません。空き時間の計算とご本人確認はツールとナビゲーターが `bookings` をワーカーの権限で読んで行い、空いている時間か埋まっている時間かだけを伝え、誰の予約かは言いません。お客様の予約は、ご本人確認が通ったあとにだけ、そのお客様の分が案内とツール結果に出ます。
- **ご本人確認**（このチュートリアルの方法）: お客様が伝えたお名前と携帯電話番号を `consult` に書くと、プログラムがすべての予約を読み、お名前（空白は無視）と電話番号（nextop の `phone` 型の鍵にそろえてから）が同じ予約だけを探します（`verified_bookings`）。合えばそのお客様の予約を案内に出し、合わなければ何も出しません。決めるのはプログラムで、ブラウザのお客様の識別子では決めません（別の端末でも、本人確認が通れば予約を探して変更できます）。予約変更ツールは処理の直前にもう一度ご本人確認をします。**実際のサービスでの本人確認（携帯電話に送った認証コードの確認など）は今後の課題です。** お名前と番号だけでは、その二つを知っているほかの人は防げません。
- **書くのは、ツールとフローの関数です。** あかりは予約も消去も自分ではしません。予約ツール（`book`）と予約変更ツール（`change_booking`）が、あかりの権限で `bookings` と `customers` に書きます（`functions/_salon.py` の `write_rows`）。ツールが書くとき、ほかの端末のチャットとほぼ同時に同じ枠を取ると、書く直前に枠を確かめるだけで、プロセスをまたいだ鍵はありません（実際のサービスは、予約をデータベースに置いて二つ目を断らせます）。フローの関数は自分の権限の行で読み（`FILES_IN`）、表に行を載せ（`_uploads`）、消します（`_deletes`）。相談の記録を消す `close_chat`、スタイリストの答えを書く `decide_booking`、例の予約を書く `seed_bookings` がそうです。
- **相談の終わり**: 「相談を終える」（チャットサーバーの `POST /api/end`）がフロー `chat_end` を動かし、そのお客様の `consult` の行を消します。終えなかった相談の行は、一日後にコアが消します（`expire_after`）。お客様の表（`customers`）と予約は残ります。
- 名前、日付、時間、料金は、モデルが書かず、予約の記録からプログラムが文に入れます。お客様へのメッセージは、スタイリストの答え（承認またはお断り）が送ります。承認とお断りのリンクには、予約番号を `APPROVE_SECRET` で署名した値（HMAC）が入っているので、メールを受け取った人だけが答えられます。
- **返信チェック**（`workers/reception/reply_check.py`）: あかりの返信は日本語だけで書きます。ひらがな、カタカナ、漢字（`々`、`〆`、`ヶ`、漢数字の零 `〇` を含む）以外の文字（ラテン文字、ハングル、キリル文字など）は断り、理由に混ざった語を入れて書き直させます。二度目も断られると、代わりの返信（`worker.json` の `reply_fallback`）が送られます。数字、記号、料金（¥8,800）、時刻（14:00）は文字ではないので通ります。メニューのスタイルの名前（`salon.json`）は、そのまま通ります。中国語は漢字で書かれていると日本語の漢字と区別できず、通ってしまいます。文字を見るだけのチェックなので、この限界は変えられません。

## 設定を埋める

### LLM (`project.json`, `workers/*/worker.json`, `.env`)

既定は OpenAI API です。`project.json` の `base_url` は `https://api.openai.com/v1`、各 `workers/*/worker.json` の `"model"` は `gpt-5.4-mini` です。`.env` の `LLM_API_KEY=` の後ろに OpenAI API キーを入れてください。ほかの OpenAI 互換 API でも動きます。`base_url` とモデル名を変えてください。

### ショートメッセージ (SMS)

既定は `.env` の `SMS_MODE=outbox` です。ショートメッセージのサービスなしで、`outbox/sms_<時刻>.txt` にファイルとして残します。

実際のメッセージに切り替えるには:
1. Twilio を使うなら、アカウントを作り、発信番号を用意します。`.env` に `SMS_MODE=twilio`、`TWILIO_ACCOUNT_SID`、`TWILIO_AUTH_TOKEN`、`TWILIO_FROM`（発信番号、`+15550100000` の形）を入れます。`functions/_notify.py` の `sms_twilio` は Twilio の文書のとおりに書いたコードで、実際のサービスにはまだ試していません。最初は自分の番号に一度送ってみてください。宛先はお客様の電話番号の鍵（E.164、`+819000007777`）で渡されます。
2. 日本国内のショートメッセージサービスを使うなら、`SMS_MODE=jp_sms` の空きスロットがあります。`functions/_notify.py` の `sms_jp_sms` は、中身のない空の関数です（呼ぶとエラーになります）。使うサービスの API の文書を読み、そこにその呼び出しを書き、設定（API キー、発信元）を `.env` に置いて `setting("JP_SMS_...")` で読みます。このチュートリアルは特定のサービスを選んでいません。
3. ほかのサービスは、`functions/_notify.py` に `def sms_xxx(to, text)` の関数を一つ書き、`PROVIDERS = {..., "xxx": sms_xxx}` に名前を入れて、`SMS_MODE=xxx` に変えます。

### 承認のリンク (`APPROVE_SECRET`, `PUBLIC_URL`)

- `.env` の `APPROVE_SECRET=` の後ろに、長くでたらめな文字列を入れます。リンクの署名に使われるので、共有しないでください。空のままだと、スタイリストへのメールは送られず、この設定を埋めるよう知らせます。
- `PUBLIC_URL` は、メールのリンクの始まりのアドレスです。既定の `http://127.0.0.1:8771` は、このコンピューターでしか開けません。スタイリストにスマートフォンで押してもらうには、スマートフォンから届くアドレスに変え、サーバーを `python chat_server.py --host 0.0.0.0` で起動します。公開サーバーがなければ、`python approve.py <予約番号>` で代わりにします。

### メール (SMTP)

`.env` の `SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASS` を埋めます。ポート 587 は STARTTLS、465 は SSL です（それ以外のポートは暗号化なしで送るので、自分のコンピューターのテスト用サーバーにだけ使ってください）。

- `MAIL_TEST_MODE=1`（既定）: スタイリストへのメールがすべて `OFFICE_EMAIL` の一か所に届きます。最初はこのままにしてください。
- 実際の運用: `MAIL_TEST_MODE=0` に変え、`salon.json` の各スタイリストの `email`（今は `example.com` の仮の値）を本当のアドレスに直します。

パスワードは `.env` にだけ書き、`.env` はアップロードや共有をしないでください（`.gitignore` に入っています）。
