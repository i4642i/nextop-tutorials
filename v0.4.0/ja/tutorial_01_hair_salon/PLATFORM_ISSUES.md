# チュートリアル 1 を作るときに見つかったプラットフォームの問題（日本版）

この版は、韓国語版のナビゲーター設計（`../../ko/tutorial_01_hair_salon`）を移したものです。その設計を作ったときに見つかった問題と、それぞれの対応は `../../ko/tutorial_01_hair_salon/PLATFORM_ISSUES.md`（nextop 0.4.0 の T1〜T6）にあります。ここには、移植で新しくわかったことだけを書きます。

## PyPI の nextop 0.4.0（2026-11-28）

`setup.bat` で新しい `.venv` に PyPI の nextop 0.4.0 を入れて確かめました（プラットフォームのソースはパスに入れていません）。`nextop check`: OK、オフラインのテスト: 45 passed。実際の相談: ローカルモデル（thinking オン）で 5 件（スタイルを選んだ予約と埋まっていた時間、一つのメッセージに二つの用件、間違った番号のあとの確認・変更・キャンセル、電話番号を断る）。プラットフォームを直して回避したことはありません。

### P1. 関数だけのフローでも、フロー検査が LLM のキーを求める（低。ko の T4 と同じ）
- `LLM_API_KEY` が空だと、`python seed.py --reset`（フロー `seed`、関数一つ、ワーカーなし）が `FlowError: the flow check failed` で止まり、`nextop check` は `[error] adapter llm.default: API key missing` と出します。このフローはモデルを呼びません。
- 影響: `.env` を書く前に例の予約を入れようとした読者は、原因のわからない失敗を見ます（setup.bat は先に `.env` を書くよう案内しています）。

### 以前の版から直っていること
- `phone` フィールド型の設定 `country`（0.3.1）が、タイプフォルダーの `type.json` で受け付けられます。bookings と customers の電話番号は `"country": "JP"` を使い、独自の部品はありません。

### メモ（モデルの問題で、プラットフォームの問題ではない）
- 言語の混ざり: 回答の下書き 27 件のうち 5 件を、日本語だけの回答検査が断りました。英単語（"Included"、"change"）のほか、一度はモデルの英語のメモと簡体字（"_style: The salon's stylist names are高桥, ..."）が回答に入り、書き直しにも "-style-" が残ったので、そのメッセージには代わりの回答（reply_fallback）が送られました。記録は残っていて、次のメッセージから続きました。お客様に混ざった回答は届いていません。架空の住所「〇〇駅」の 〇 を断った 1 件は検査の誤りで、〇 を通すように直しました。
- 施術準備のメモ（社内向け、回答検査なし）に一度 "pending" と "SMS" が入りました。
- 言葉づかい: お客様が「高橋さん」と言うと、モデルも自分の店のスタイリストに「さん」を付けることがあります。プログラムが時間を確かめる前に「承りました」と言うことがあります。
