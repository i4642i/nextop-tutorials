# 튜토리얼 1. 헤어샵 예약 상담 챗봇

손님과 채팅으로 상담합니다. 예약 담당 직원 "하나"는 손님의 용건(가게 안내, 예약, 내 예약 확인, 예약 변경이나 취소, 그 밖의 용건)을 찾고, 용건마다 필요한 것을 묻고, 들은 것을 표에 한 줄씩 기록합니다. 무엇이 아직 남았는지, 지금 어느 단계인지는 직원이 아니라 프로그램(**대화 내비게이터**)이 기록을 보고 정합니다. 예약이 잡히면 디자이너에게 상담 요약 메일이 가고(대화 전체가 첨부되고 승인과 거절 링크가 들어 있습니다), 디자이너가 승인하면 그때 손님에게 확정 문자가 갑니다.

## 완성하면 이렇게 됩니다

살롱 하루(예시 가게)에는 디자이너 세 명(지수 원장, 민호 실장, 서연 디자이너)이 있고, 며칠 치 예약이 이미 차 있습니다.

상담은 이렇게 흘러갑니다.

```
인사 → 용건 찾기 → 용건마다 하나:
                    - 가게 안내: 가게 안내 문서에서 찾아 답하기
                    - 예약: 성함, 휴대폰 번호, 시술, 머리 길이, 원하는 날짜와 시간, 디자이너(선택),
                            시술별 질문(salon.json), 빈 시간 하나에 손님 동의 → 예약
                    - 내 예약 확인: 성함과 휴대폰 번호로 본인 확인 → 예약 알려 주기
                    - 예약 변경이나 취소: 본인 확인 → 어느 예약, 변경인지 취소인지, 바꿀 시간(취소 이유는 선택)
                    - 그 밖의 용건: 무슨 일인지(휴대폰 번호는 선택) → 가게에서 전화
      → "더 도와드릴 일이 있을까요?" (다시 용건 찾기) → 마무리
상담이 끝나면 흐름이 상담 기록을 지웁니다.
```

- 하나가 하는 일은 손님과 말하고, 들은 것을 저장 도구(`put`)로 상담 메모 표(`consult`)에 적는 것입니다. 같은 항목을 다시 적으면 그 줄이 새 값으로 바뀌고 예전 값은 이력에 남습니다(손님이 염색에서 펌으로 마음을 바꾸면 `service` 줄 하나가 바뀝니다).
- 질문마다 **대화 내비게이터**(`workers/reception/navigator.py`)가 기록을 체크리스트(`checklists.json`, `salon.json`)와 맞춰 보고 단계(상담 `consult`, 예약 `booking`, 예약 확인과 변경 `manage`)와 **단계 안내**를 정합니다. 단계 안내는 "예약: 고객과 대화하며 예약에 필요한 정보를 수집합니다. 남은 것: ..."처럼 남은 항목과 기록된 항목을 말합니다. 하나가 `put`을 하면 내비게이터가 다시 불려, 같은 차례 안에서 안내가 바로 바뀝니다.
- 예약 도구(`book`)는 예약 단계에만 있습니다. 예약 단계는 동의를 뺀 예약 항목이 다 기록되었을 때만 열립니다. 원하는 시간이 이미 찼거나 디자이너가 쉬는 날이면 안내가 그렇다고 말하고, 빈 시간 도구(`find_times`)로 가까운 빈 시간을 찾아 다시 동의를 받게 합니다. 동의는 마지막으로 정한 시간에 대해서만 셉니다.
- 내 예약 확인과 변경, 취소는 **본인 확인**이 먼저입니다. 손님이 준 성함과 휴대폰 번호를 프로그램이 예약 기록과 맞춰 보고(브라우저 번호가 아니라), 맞을 때만 그 손님의 예약을 보여 주고 바꿉니다. 번호가 틀리면 다른 손님의 예약이 있는지조차 말하지 않습니다.

**실제 실행 예** (모델: 로컬 qwen, nextop 0.4.0.dev12, 손님도 같은 모델이 연기. 손님은 이미 찬 시간을 원합니다. 모델과 실행마다 말투는 조금씩 달라집니다. 다른 상담의 결과는 아래 "실제로 돌려 본 결과" 절에 있습니다.)

## 만드는 데 걸리는 시간과 준비물

약 1시간. 이미 만들어진 프로젝트를 읽고 설정을 채워 돌려 보는 튜토리얼입니다.

- Python 3.11~3.13과 nextop 0.4.0: 아래 0단계의 `setup.bat`이 모두 설치합니다(직접 하려면 `pip install -r requirements.txt`). 이 튜토리얼은 nextop 0.4.0의 대화 내비게이터와 파일 서버(유형 폴더, 공통 도구, 보여 줄 깊이)로 쓰였습니다. 0.4.0이 PyPI에 올라가기 전에는 받은 휠 파일로 설치합니다: `setup.bat <휠 파일 경로>`. `requirements.txt`가 nextop 0.4.0을 고정하고 `project.json`의 `"nextop": ">=0.4,<0.5"`가 이 프로젝트에 필요한 버전을 알립니다(다른 버전이면 `nextop check`가 어떻게 고치는지 알려 줍니다).
- OpenAI API 키 (기본값입니다. 다른 OpenAI 호환 API도 됩니다. 아래 설정 참고)
- 메일 보내는 계정의 SMTP 정보 (선택, 없으면 메일 단계만 건너뜁니다)
- 문자 서비스는 없어도 됩니다. 기본값은 파일로 남기는 `outbox` 방식입니다.

모델이 없어도 3단계까지는 지금 바로 할 수 있습니다. 프로그램 부분(내비게이터, 시간 계산, 겹침 거절, 본인 확인, 문자, 메일)은 모델 없이 시험 코드로 확인합니다.

## 이 튜토리얼로 배우는 nextop 기능

- 직원 방식(`"mode"`): 손님과 채팅하는 자유 질문 직원(하나, `"ask"`)과 정해진 일을 하는 고정 업무 직원(누리, 두리, `"task"`)을 나누기
- 대화 내비게이터(`navigator.py`)와 단계 안내: 질문마다 기록을 보고 단계와 안내를 정하는 사용자 코드. 단계마다 쓸 수 있는 도구와 파일 서버가 다릅니다(예약 도구는 예약 단계에만)
- 임무(`mission.md`, 모든 단계에 같은 원칙), 단계 글(`steps/<id>.md`), 페르소나(`persona.md`, 누구인지와 말투)
- 체크리스트를 코드가 아니라 명세 파일(`checklists.json`, `salon.json`)에 두기. 표의 고르기 칸(`choice`)이 같은 파일에서 항목 번호를 읽는 프로젝트 부품(`parts/field_type/choice.py`)
- 표 파일 서버와 열쇠: 같은 항목은 덮어쓰고 이력을 남기기(`consult`), 보여 줄 깊이(`"show": 2`)로 직원의 입력에 표의 줄을 바로 보여 주기
- 권한과 범위: 채팅의 손님 번호(`_subject`)로 자기 기록만 읽게 하기. 예약 기록(`bookings`)은 직원이 아예 못 보고 함수만 읽고 쓰기
- 함수 블록과 작은 흐름: 쓰기는 함수가 합니다(`FILES_IN`, `_uploads`, `_deletes`). 도구는 파일 서버를 읽기만 하므로, 써야 하는 도구는 작은 흐름을 돌립니다
- 만료(`expire_after`): 끝나지 않은 상담의 기록은 하루 뒤에 코어가 지움
- 글 유형과 bm25 검색: 가게 안내 문서(`shop_info`)를 찾아 답하기(도구 `query`, `get`)
- 모델 없이 하는 시험: 가짜 LLM으로 대화와 흐름 전체 검증

## 단계별 따라 하기

PowerShell에서 이 폴더(`ko/tutorial_01_hair_salon`)로 이동해 시작합니다.

### 0. 설치: setup.bat 실행

이 폴더의 `setup.bat`을 두 번 클릭하거나, PowerShell에서 `.\setup.bat`을 실행합니다. 처음 한 번 필요한 것을 모두 자동으로 설치합니다.

- Python 3.11~3.13을 찾습니다. 없으면 winget으로 Python 3.12를 설치합니다(설치 뒤 터미널을 새로 열고 `setup.bat`을 다시 실행)
- 이 폴더에 가상 환경 `.venv`를 만들고 `requirements.txt`(nextop, pytest)를 설치합니다. `setup.bat C:\받은폴더\nextop-0.4.0...whl`처럼 휠 파일 경로를 주면(또는 환경 변수 `NEXTOP_WHEEL`) nextop만 그 파일로 설치합니다. 휠 파일은 파이썬 버전에 맞아야 합니다(`cp311`이면 Python 3.11)
- `.env`가 없으면 `.env.example`을 복사해 만들고, 채워야 할 이름만 보여 줍니다
- 모델 없이 하는 시험을 돌리고, 모두 통과하면 마지막에 `Setup OK`와 깔린 nextop 버전이 나옵니다

여러 번 실행해도 됩니다(이미 있는 `.venv`와 `.env`는 그대로 둡니다). 아래 명령은 가상 환경을 켠 뒤 실행합니다.

```powershell
.venv\Scripts\activate
```

### 1. 폴더 구조 보기

```

salon.json            디자이너(근무 요일, 시간), 시술 가격과 시간, 시술별 체크리스트(손님에게 미리 물을 것)
checklists.json       용건마다의 체크리스트(가게 안내, 예약, 내 예약 확인, 변경과 취소, 그 밖의 용건)와
                      단계 안내의 문장 전부(texts). 코드에는 체크리스트도 안내 문장도 없습니다
data/seed_bookings.json   이미 잡혀 있는 예약 (오늘 기준으로 만들어짐)
workers/reception     하나 (자유 질문 직원, "mode": "ask")
  persona.md            누구인지와 말투
  mission.md            모든 단계에 같은 일하는 원칙(기록하는 법, 사실은 도구 값만)
  steps/consult.md      상담 단계: 용건 찾기, 가게 안내, 예약 정보 모으기
```

`9 example bookings written`이 보이고 시험은 `26 passed`가 보이면 됩니다. `schedule.html`을 브라우저로 열면 날짜별 표에 확정된 예약이 파란 칸으로 보입니다(승인을 기다리는 예약은 점선 칸). 시험이 확인하는 것:

- 용건이 없으면 상담 단계, 안내는 "무엇을 도와드릴지 묻기"
- 예약 용건이면 남은 항목을 항목 번호(`name`, `phone`, `wish_time`, 시술별 `color_want` ...)로 대고, 기록된 시술의 질문만 셉니다
- 동의를 뺀 예약 항목이 다 기록되면 예약 단계. 원하는 시간이 비어 있으면 "제안하고 동의 받기", 동의가 기록되면 "예약 도구로 예약"
- 원하는 시간이 찼으면 안내가 다른 시간을 찾으라고 하고, 동의가 있어도 예약 도구가 거절합니다. 동의 뒤에 시간을 바꾸면 동의를 다시 받아야 합니다
- 같은 항목을 다시 적으면 마지막 값이 남고(이력에 예전 값), 시술을 바꾸면 그 시술의 질문으로 바뀝니다
- 한 메시지의 용건 둘(예약과 주차 문의)이 모두 안내에 나옵니다
- 꼴이 틀린 답(전화번호, 날짜, "한지민이에요" 같은 성함)은 다시 받으라고 하고, 명세에 없는 항목 번호는 코어가 받지 않습니다
- 다른 손님의 채팅에는 기록이 보이지 않습니다
- 예약 도구는 상담 단계에서는 주어지지 않습니다. 채팅에서 예약하면 예약 기록, 달력, 손님 표, 본인 확인 결과가 모두 쓰이고, 예약 용건은 프로그램이 끝남으로 적으며, 그 예약의 체크리스트 줄은 지워집니다
- 본인 확인: 번호가 틀리면 아무것도 알려 주지 않습니다. 다른 브라우저에서도 성함과 번호가 맞으면 예약을 찾습니다. 본인 확인 뒤에 번호가 바뀌면 다시 확인합니다
- 변경과 취소: 본인 확인 전에는 거절, 다른 손님의 예약은 거절. 취소하면 그 시간이 다시 비고, 시간을 바꾸면 다시 승인 대기
- 누리의 상담 요약과 두리의 메모가 디자이너 메일에 실리고, 승인 링크는 한 번만 듣습니다
- 예약이나 취소를 처리한 그 차례에는 안내가 "방금 처리했다"와 지금의 예약 상태를 말합니다
- 상담이 끝나면 그 손님의 상담 기록과 본인 확인 결과만 지워집니다

## 어떻게 동작하나

```
[손님 채팅 화면] --메시지--> chat_server.py --> 하나 (reception, ask)
 (대화 + 손님 번호)                             |
                             navigator.py: consult / identity / schedule 표를 읽고 단계와 단계 안내를 정함
                                                |
          consult 단계  도구: price_quote, put, get, query
          booking 단계  도구: find_times, book, price_quote, put, get, query
          manage 단계   도구: verify_customer, find_times, change_booking, put, get, query

book            --> 흐름 book (take_booking: bookings, schedule에 쓰기, 시간을 다시 확인)
                --> 흐름 booked (after_booking: 예약 용건 끝남, 그 체크리스트 줄 지우기, customers에 머리 이력)
                --> 흐름 verify (match_customer: identity에 이 손님의 예약 목록)
                --> chat_server가 뒤에서 흐름 booking_notes: load_visit --> 누리(요약) --> 두리(메모) --> mail_designer
verify_customer --> 흐름 verify
change_booking  --> 흐름 verify (다시 본인 확인) --> 흐름 change (apply_change: 쓰기, 디자이너에게 알림)
                --> 흐름 changed (after_change) --> 흐름 verify
상담 끝내기     --> 흐름 chat_end (close_chat: 이 손님의 consult, identity 줄 지우기)
디자이너 링크    --> 흐름 decide (decide_booking: 확정 또는 거절, 손님에게 문자)
```

- **기록과 판단을 나눕니다.** 손님 말의 뜻을 알아듣고 기록하는 것은 하나(LLM)의 일이고, 그 기록으로 무엇이 남았는지, 시간이 비었는지, 본인이 맞는지, 지금 어느 단계인지는 프로그램이 정합니다. 그래서 하나에게 "가격 도구는 한 번만" 같은 덧붙인 규칙이 없습니다.
- **용건 줄**: 하나는 용건마다 `purpose_<id>` 줄(`words`: 손님이 한 말, `state`: `open`)을 남깁니다. 한 메시지에 용건이 둘이면 두 줄입니다. 예약과 변경 용건은 프로그램(흐름의 함수)이 끝남(`done`)으로 적고, 가게 안내와 내 예약 확인은 하나가 답한 뒤 적습니다. 진행 중인 예약, 확인, 변경 용건 가운데 먼저 적힌 것이 단계를 고르고, 가게 안내와 그 밖의 용건은 어느 단계에서든 안내에 함께 나옵니다.
- **덮어쓰기와 이력**: `consult`의 열쇠가 `item`이라 같은 항목을 다시 쓰면 그 줄이 바뀌고 예전 값은 줄의 `history`에 남습니다. 손님마다 따로라서(열쇠에 손님 번호가 들어감) 다른 손님의 같은 항목과 섞이지 않습니다.
- **보여 줄 깊이**: `consult`, `identity`, `customers`의 권한 줄에 `"show": 2`가 있어서, 하나의 입력에 그 표의 줄이 칸 값과 함께 바로 나옵니다. 하나는 `list`를 부르지 않고도 기록과 예약 상태를 봅니다.
- **동의**: 예약 단계의 `agree`는 원하는 시간(`wish_time`)과 디자이너(`designer`)가 마지막으로 바뀐 뒤에 적혔을 때만 셉니다(줄의 `updated` 시각으로 비교). 그 시간이 비어 있지 않으면 동의가 있어도 세지 않고, 안내가 다른 시간을 찾게 합니다. 예약 도구도 같은 규칙으로 다시 확인하고, 마지막으로 `take_booking`이 달력을 다시 읽어 확인합니다.
- **예약 기록은 하나가 못 봅니다.** `bookings`의 권한 표에는 함수만 있습니다. 빈 시간은 이름과 번호가 없는 달력(`schedule`)으로 찾고, 손님의 예약은 본인 확인을 거쳐 `identity`로만 봅니다.
- **본인 확인**(이 튜토리얼의 방법): 손님이 준 성함과 휴대폰 번호를 `consult`에 적으면, 본인 확인 도구가 흐름 `verify`를 돌리고, 그 함수(`match_customer`)가 모든 예약을 읽어 성함(띄어쓰기 무시)과 번호(꼴을 맞춘 뒤)가 똑같은 예약만 찾습니다. 맞으면 `identity`에 `verified: yes`와 그 손님의 예약 목록을, 아니면 `verified: no`만 적습니다. 결정은 프로그램이 하고, 브라우저의 손님 번호로 정하지 않습니다(다른 기기에서도 본인 확인이 되면 예약을 찾고 바꿀 수 있습니다). 변경 도구는 처리하기 직전에 본인 확인을 다시 합니다. **실제 서비스의 본인 확인(휴대폰으로 보낸 인증 번호 확인 등)은 앞으로 할 일입니다.** 성함과 번호만으로는 그 둘을 아는 다른 사람을 막지 못합니다.
- **쓰기는 함수가 합니다.** 도구는 파일 서버를 읽기만 할 수 있어서(그 직원의 권한으로), 써야 하는 도구는 작은 흐름을 돌립니다(`functions/_salon.py`의 `run_flow`). 흐름의 함수는 자기 권한 줄로 읽고(`FILES_IN`), 표에 줄을 올리고(`_uploads`, 줄이 든 `.json` 파일을 그 표로), 지웁니다(`_deletes`). 영구 기록(`customers`)도 하나가 아니라 예약 흐름의 함수가 씁니다.
- **상담 끝**: "상담 끝내기"(채팅 서버의 `POST /api/end`)가 흐름 `chat_end`를 돌려 그 손님의 `consult`와 `identity` 줄을 지웁니다. 끝내지 않은 상담의 줄은 하루 뒤 코어가 지웁니다(`expire_after`).
- 이름, 날짜, 시간, 가격은 모델이 쓰지 않고 예약 기록에서 프로그램이 문장에 넣습니다. 손님 문자는 디자이너의 답(승인 또는 거절)이 보냅니다. 승인과 거절 링크는 예약 번호를 `APPROVE_SECRET`으로 서명한 값(HMAC)이 들어 있어서, 메일을 받은 사람만 답할 수 있습니다.

여덟 상담 모두 끝난 뒤 `consult`와 `identity`에는 줄이 하나도 남지 않았고(상담 끝 흐름이 지움), `customers`에는 예약한 네 손님의 머리 이력이 남았습니다. 모델 주소와 키는 실행하는 동안 메모리에만 있었고, 기록(`runs/`, 메일, 메모)에서 찾아보니 0건이었습니다.

세 번 돌리며 찾아서 고친 것(모두 이 튜토리얼 안에서):
- 예약이나 변경을 마친 바로 그 차례에 단계가 상담으로 바뀌면서 앞 단계의 도구 결과가 넘어가지 않아, 하나가 "이미 그 시간으로 되어 있어요", "이미 취소된 상태예요"라고 말했습니다. 내비게이터가 이 질문에서 들어간 단계(`ctx["entered"]`)를 보고 "방금 처리했습니다"와 지금의 예약 상태를 안내에 넣게 했습니다.
- 손님이 "한지민이에요"라고 하면 그대로 성함에 적혀 예약과 본인 확인이 틀어졌습니다. 성함 항목에 꼴(`"format": "name"`, 이름만)을 정해 안내가 "이름만"이라고 말하고, 문장 끝이 붙은 이름은 다시 받게 했습니다.
- 상담 단계에서 빈 시간을 볼 수 없는데 "11시 반 가능해요"라고 말한 일이 있어, 상담 단계 글에 그 사실을 적었습니다.
- 안내가 남은 항목을 말했는데도 하나가 물어보지 않고 상담을 끝낸 일이 있어(예약은 프로그램이 막아서 잡히지 않음), 안내 끝에 "다음에 물을 것"을 하나 넣었습니다.

모델이 남긴 실수(프로그램이 막거나 결과에 영향이 없었던 것): 가끔 한국어 답에 다른 나라 글자가 섞입니다("锁骨", "沙龙" 등). 상담 요약의 `wishes`에 원하는 스타일 대신 예약 시간 부탁이 들어가기도 합니다. 취소는 손님이 "취소"라고 하고 예약이 정해지면 바로 처리됩니다(체크리스트에 취소 확인 항목이 없습니다).

## 설정 채우기

### LLM (`project.json`, `workers/*/worker.json`, `.env`)

기본값은 OpenAI API입니다. `project.json`의 `base_url`은 `https://api.openai.com/v1`, 각 `workers/*/worker.json`의 `"model"`은 `gpt-5.4-mini`입니다. `.env`의 `LLM_API_KEY=` 뒤에 OpenAI API 키를 넣으세요. 다른 OpenAI 호환 API도 됩니다. `base_url`과 모델 이름을 바꾸세요.

### 문자 (SMS)

기본값은 `.env`의 `SMS_MODE=outbox`입니다. 문자 서비스 없이 `outbox/sms_<시각>.txt`에 파일로 남깁니다.

실제 문자로 바꾸려면:
1. 문자 서비스에 가입하고 발신번호를 등록합니다. 지금 코드가 준비해 둔 곳은 Solapi입니다.
2. `.env`에 `SMS_MODE=solapi`, `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`, `SOLAPI_SENDER`(등록한 발신번호)를 채웁니다.
3. 주의: `functions/_notify.py`의 `sms_solapi`는 Solapi 문서대로 쓴 코드이며 실제 서비스에는 아직 시험하지 않았습니다. 처음에는 본인 번호로 한 번 보내 보세요.
4. NHN Cloud 등 다른 서비스는 `functions/_notify.py`에 `def sms_nhn(to, text)` 함수를 하나 쓰고 `PROVIDERS = {..., "nhn": sms_nhn}`에 이름을 넣은 뒤 `SMS_MODE=nhn`으로 바꿉니다.

### 승인 링크 (`APPROVE_SECRET`, `PUBLIC_URL`)

- `.env`의 `APPROVE_SECRET=` 뒤에 길고 아무렇게나 쓴 글자를 넣습니다. 링크 서명에 쓰이니 공유하지 마세요. 비어 있으면 디자이너 메일이 나가지 않고 이 설정을 채우라고 알려 줍니다.
- `PUBLIC_URL`은 메일 링크가 시작하는 주소입니다. 기본값 `http://127.0.0.1:8771` 은 이 컴퓨터에서만 열립니다. 디자이너가 휴대폰에서 누르게 하려면 휴대폰이 닿는 주소로 바꾸고, 서버를 `python chat_server.py --host 0.0.0.0` 으로 켭니다. 공개 서버가 없으면 `python approve.py <예약 번호>`로 대신합니다.

### 메일 (SMTP)

`.env`의 `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`를 채웁니다. 포트 587은 STARTTLS, 465는 SSL입니다(그 밖의 포트는 암호화 없이 보내므로 내 컴퓨터의 시험 서버에만 쓰세요).

- `MAIL_TEST_MODE=1`(기본): 모든 디자이너 메일이 `OFFICE_EMAIL` 한 곳으로 갑니다. 처음에는 이대로 두세요.
- 실제 운영: `MAIL_TEST_MODE=0`으로 바꾸고 `salon.json`의 각 디자이너 `email`(지금은 `example.com` 자리표시)을 실제 주소로 고칩니다.

비밀번호는 `.env`에만 쓰고, `.env`는 올리거나 공유하지 마세요(`.gitignore`에 들어 있습니다).
